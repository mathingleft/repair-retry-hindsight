## `CE_m` bootstrap reconciliation

The maintained sequential helper carries all `CE_m`-family contrasts jointly:
it builds one 10,000-by-11 paired problem-index matrix per model with
`random.Random(0)` and repeated `randrange`, reuses that matrix for every contrast,
and takes sorted percentile endpoints. This exactly reproduces the Qwen review
bounds. Three DeepSeek endpoints differ by one 0.9 pp grid step from the
review-time table: `CE-CE_m` is `[-5.5, 9.1]` rather than `[-5.5, 10.0]`, the
matched interaction is `[0.9, 35.5]` rather than `[0.9, 34.5]`, and `CE_m-C` is
`[-10.0, 6.4]` rather than `[-10.9, 6.4]`. No historical script or RNG-consumption
order supporting the alternate endpoints was recovered, so the artifact reports
the reproducible maintained-helper values rather than encoding ad hoc RNG offsets.

## Record schemas

One-step keys are `(arm,id,sample_idx)` and verdicts use `status`; proof text is
`lean_code`. Compact adaptive keys are `(id,traj,attempt)` and proof text is
`code`. Full and memoryless keys are `(problem_id,trajectory_id,attempt_id)`;
verdicts use `verification_result`, proofs `extracted_proof`, diagnostics
`compiler_output`. `analysis/common.py` normalizes these names explicitly.
Attempt indices run 1–64; sample identities are keys, not unique random seeds.
Large records are stored as `.xz`; `scripts/unpack_data.py` restores the original
JSON Lines files. The omitted full traces are redundant with the included compact
records; the donor projections needed for the matching audits are retained.

## Reported results and qualitative examples

`check_reported_results.py` compares independent sample-level recounts against
numeric tables in `expected/reported_results.json`: one-step counts, EXT3 totals,
instruction ablations, both sequential horizon/contrast tables, copying,
subgroup summaries, and compute totals. It performs 236 numerical comparisons
without manuscript files. Output: `generated/reported_result_checks.json`.

`export_examples.py` locates the precise problem/arm/sample keys for the appendix
examples and exports full records and predecessors to
`generated/behavioral_examples.json`. It checks both the matching-proof example
and the mixed outcomes in the reflection/diagnostic example.
